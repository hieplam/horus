# Plan: port horus to Go (Phase 1)

Spec: [`../specs/2026-11-10-go-port.md`](../specs/2026-11-10-go-port.md).
Tracking issue of the whole goal: [#4](https://github.com/hieplam/horus/issues/4).

## How to read this plan

- This file on `main` wins over the copy of a section in an issue.
- One section is one task and one pull request. The section id (`G0` to `G12`)
  is also in the issue title.
- A goal row is named by its id in the spec: `contract`, `graph`,
  `workflow-cli`, `downloader`, `setup-commands`, `builds`, `real-image`,
  `no-python`.
- Evidence goes to [`2026-11-10-go-port-evidence.md`](2026-11-10-go-port-evidence.md):
  one `## <task id>` section for each task, with the literal output of Red and
  Green. Decisions made under the standing rules go to its `## Decisions`
  section.
- The source of truth for behaviour is the old code. Read the file that you
  port, in full, before you write its Go package. Read the port map in issue #4
  for what must stay the same.
- Each pull request body has `Closes #<issue>` and a `## Verify` section with
  Red, Green, Stub check and Ratchet, each with its literal result.
- Before each pull request: `python scripts/lint-public.py` exits 0, and
  `gofmt -l .` prints nothing.
- "The contract test against Go" means:
  `python tests/mcp_contract.py --server-cmd <path of horus> mcp`
  with Python 3.12 and `mcp==2.3.0`. Until `G10`, the test also needs the repo
  checkout, because it imports `horus/errors.py`.
- Baseline measured on 2026-11-10 at commit `c5379f9`: the contract test
  against the Python server prints `contract: 30 of 30 passed`. `horus/*.py`
  plus `scripts/*.ps1` have 2,827 lines.

Order: `G0`, then `G1`. After `G1`, three lanes can run side by side:
`G2` then `G7`; `G3` then `G4` then `G5`; `G6`. Then `G8`, `G9`, `G10`, `G11`,
`G12` in that order.

`docs/plans/2026-11-10-go-port-evidence.md`, `docs/mcp.md` (the check count).

Steps:

   `goal: N of 8 rows passed`. It exits 0 only when N is 8.

     Default: `horus mcp` from the PATH.

   - `workflow-cli`: `python tests/workflow_parity.py` exits 0.
   - `downloader`: `go test ./internal/scripts/downloadmodel` passes and ran at

## G3 - Downloader: `horus download-model`

Blocked by: `G1`.

Ports: `scripts/download-model.ps1`.

Files: `internal/scripts/downloadmodel`, `cmd/horus`.

Steps:

1. Read `download-model.ps1` in full. Keep its flags (in Go style), its text
   output and its exit codes.
2. Download with `net/http` to `<dest>.part`, resume with a `Range` header,
   retry, then check the size and the SHA-256, then rename. Never overwrite a
   file that it did not write. Refuse when the free space is under the file
   size plus 1 GiB.
3. Read `HF_TOKEN` from the environment or from `.env`, in this package only.
   Send it as a header, only when the host is `huggingface.co` or ends with
   `.huggingface.co`. Drop the header when a redirect leads to another host.
4. Keep the four outcomes that `models.py` reads: HTTP 401, HTTP 403, not
   enough free space, refusal to overwrite.

### Verify

- **Goal:** row `downloader`.
- **Red:** `go test ./internal/scripts/downloadmodel` fails: no such package.
- **Green:** `go test ./internal/scripts/downloadmodel -v` passes with one
  test for each case, against a local fake HTTP server:
  1. a full download with the right size and SHA-256;
  2. resume from a `.part` file (the server sees a `Range` header);
  3. retry after a broken connection;
  4. wrong size, the file is not put in place;
  5. wrong SHA-256, the file is not put in place;
  6. a different file with the same name is not overwritten;
  7. free space under the size plus 1 GiB is refused;
  8. HTTP 401 and HTTP 403 give the two outcomes;
  9. the token header goes to a `huggingface.co` host, does not go to another
     host, and is dropped on a redirect to another host;
  10. the token is in no URL, no argument and no output line.
  `python tools/goal_check.py --no-ci` shows `PASS  downloader`.
- **Stub check:** a downloader that writes nothing fails case 1, because the
  test reads the file and its SHA-256. A downloader that always sends the
  token fails case 9, because the fake server records the headers.
- **Ratchet:** `goal` goes up by 1.
