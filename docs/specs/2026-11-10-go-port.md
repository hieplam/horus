# Spec: port horus to Go (Phase 1)

Date: 2026-11-10. Tracking issue of the whole goal:
[#4](https://github.com/hieplam/horus/issues/4). Plan:
[`../plans/2026-11-10-go-port.md`](../plans/2026-11-10-go-port.md).

## What this phase delivers

One Go program, `horus`, that does everything that the Python package `horus/`
and the PowerShell scripts in `scripts/` do today, with the same behaviour.
After this phase horus itself needs no Python and no PowerShell. The machine
still needs Python, because ComfyUI is a Python program.

Terms:

- **Port:** a rewrite in another language that keeps the behaviour.
- **Contract test:** `tests/mcp_contract.py`. It starts a server over stdio,
  answers its ComfyUI calls with a fake ComfyUI, and prints
  `contract: N of M passed`.
- **Goal row:** one outcome that a user sees, with the command that proves it.
- **Golden file:** a committed file that holds the output of the old code. A
  test compares the output of the new code with it.

## Rules of the port

1. **Same behaviour.** The same 5 tools, schemas, annotations, `instructions`
   text, envelope, and the 21 error codes with the same `retryable` and
   `action_by`. The same environment variables and `.env` lookup.
2. **Same shape.** One Go package for each Python module and each script. Each
   Go file starts with a comment that names the file that it ports.
3. **Changes only where Go or macOS forces them.** No `powershell.exe`, no
   `curl.exe`. Flags take Go style (`-Json` becomes `-json`,
   `-WorkflowsDir` becomes `-workflows-dir`). A message that named a `.ps1`
   script names the `horus` subcommand.
4. **The contract test is the spec.** It changes in two places only, and only
   in the switch-over task: the default server command, and where it reads the
   list of error codes.
5. **Licenses.** `comfy-mcp` (AGPL) and `comfy-cli` (GPL) run only as separate
   processes. horus never imports or copies their code.
6. **The token.** Only the download code reads `HF_TOKEN`. It sends the token
   in a header, only to `huggingface.co` hosts. The token never appears in a
   URL, a command line or a log. `horus mcp` never reads it.

## Design decisions of this phase

| Topic | Decision |
|---|---|
| Module path | `github.com/hieplam/horus` |
| MCP library | The official Go SDK `github.com/modelcontextprotocol/go-sdk`. The skeleton task confirms that it supports output schemas, `structuredContent` with `isError`, tool annotations, `instructions` and progress notifications. If it lacks one, that task files an issue. |
| Layout | `cmd/horus/main.go`, `internal/server`, `internal/herr`, `internal/catalog`, `internal/comfy`, `internal/generate`, `internal/models`, `internal/settings`, `internal/scripts/<command>`. |
| Process boundary | `horus mcp` starts `horus workflow <action> -json` as a child process and parses its `HORUS_JSON` line, as `models.py` does with `workflow.ps1`. It finds the binary with `os.Executable()`. |
| Repo root | `HORUS_ROOT`, then the nearest folder above the current folder that has `workflows/`, then the folder of the executable. |
| OS-specific code | Only for starting and killing a process tree: one file pair (`_windows.go`, and `//go:build darwin \|\| linux`). |
| Download failures | The Go downloader keeps the four outcomes that `models.py` reads from text: HTTP 401, HTTP 403, not enough free space, refusal to overwrite. They map to `HF_TOKEN_INVALID`, `LICENSE_NOT_ACCEPTED`, `DISK_FULL` and `FILE_CONFLICT`. |
| 7-Zip | `horus install-comfyui` calls `7z.exe`, as today. |
| `install-workflow-models.ps1` | Dropped. `horus workflow install` and `horus workflow check` replace it. |
| Development build | `go install ./cmd/horus` puts `horus` on the PATH. CI builds with `go build -o bin/`. `bin/` is ignored by git. |
| Error codes for the contract test | `horus errors -json` prints the code table. After the switch-over the contract test reads it from there. |
| Test tools | `tests/mcp_contract.py`, `tests/workflow_parity.py`, `tools/goal_check.py` and `scripts/lint-public.py` stay Python. No user runs them. |

## Standing rules

- A plan command that no longer fits the tree: use the equivalent command that
  proves the same goal row, and record why. Never weaken what a row proves.
- A flaky test: fix the root cause. No retries, no longer sleeps, no looser
  assertions.
- Never weaken or delete a test to make Green pass.
- Another heavy job on the PC (for example an image run of another session):
  wait until the GPU is free, run again one time, record both runs.
- The Go code and the old code disagree: the old code is right, unless the
  difference is one that rule 3 allows. Record each allowed difference in the
  evidence log.
- Decisions go to the "Decisions" section of the evidence log.
